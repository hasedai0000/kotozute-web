# ことづて ― 画面設計・仕様書（全画面 / v1.1）

対象：MVP の全画面（ダッシュボード、セクション編集、家族・共有管理、LP、ログイン／登録、招待受諾、大切な人へ、プレビュー／書き出し、設定）と、v1 の死後開示（発動・撤回）。

## 共通仕様

### ロールによる出し分け（YOU MUST）

| | owner（本人） | family（家族） |
|---|---|---|
| 編集 | 可 | **不可**（閲覧のみ。編集 UI 自体を出さない） |
| `always` の項目 | 見える | 見える |
| `posthumous` の項目 | 常に見える（鍵バッジ付き） | **`disclosed_at` が立つまで存在しない**（API が返さない） |
| 公開タイミングの変更 | 可 | 不可 |

家族側は「隠す」のではなく **API が返さない**。クライアントで非表示にするだけの実装は禁止。

### 状態の出し分け（全画面共通）

| 状態 | 表示 |
|---|---|
| ローディング | スケルトン（レイアウトを保つ。スピナー単体は使わない） |
| 空 | 説明文＋一次アクション（例「まだ登録がありません／口座を追加」） |
| エラー | 内容と再試行ボタン。原因が権限なら「閲覧権限がありません」 |
| 保存中 | 楽観的更新で即時反映、失敗時はロールバック＋トースト |
| オフライン／通信失敗 | 「保存できませんでした」トースト＋再試行 |

### 共通コンポーネント

`TimingBadge`（常時共有＝グリーン／死後開示＝アンバー＋鍵）、`EntryCard`、`SectionProgress`、`EmptyState`、`ConfirmDialog`。

# 1. ダッシュボード `/dashboard`

## 目的
「今どこまで書けたか」を一目で示し、続きへ送り出す。

## レイアウト（上から）
1. ヘッダー：ロゴ、ナビ（ホーム／ノート／家族）、ユーザーメニュー
2. 挨拶＋全体進捗：`記入済み {n} / {total}`、進捗バー
3. **次にやること**（1 件）：未記入が多いセクションへの導線
4. セクションカード一覧（7 領域＋大切な人へ）：アイコン、名称、`{filled}/{total}`、進捗バー
5. 家族の共有状況：招待済みメンバーのアバターと人数、`/family` への導線

## 仕様
- 進捗＝`記入済み項目数 ÷ 全項目数`。`note_fields` は値あり、`note_entries` は 1 件以上で「記入済み」。
- 家族ロールでは「次にやること」を出さず、閲覧向けの文言にする。
- 未招待（メンバー 0 人）の場合、**「家族を招待しませんか」を目立つ位置に出す**（＝常時共有が成立していない＝本サービスの価値が未達のため）。
- セクションカード押下 → `/notebook/[section]`。

# 2. セクション編集 `/notebook/[section]`

## 目的
各領域を、迷わず・少しずつ書けるようにする。**8 領域を 1 実装で賄う。**

## レイアウト
1. パンくず（マイノート ＞ セクション名）、セクション名、進捗
2. 説明文（そのセクションで何を残すか。1〜2 行）
3. 機微情報の注意（money / digital のみ）：「暗証番号・パスワードは書かないでください」
4. **単一項目**（`note_fields`）：フォーム。自動保存
5. **リスト項目**（`note_entries`）：`EntryCard` の一覧＋「＋ 追加」ボタン
6. 前後のセクションへの導線

## 仕様（単一項目）
- 入力後 **debounce 800ms で自動保存**。保存状態を「保存中…／保存しました」で示す。
- 失敗時はトースト＋再試行。値は画面に保持する（消さない）。

## 仕様（リスト項目＝口座・保険等）
- カード表示：主要名（例 銀行名）、副項目（支店・種別・下 4 桁）、`TimingBadge`、編集・削除。
- 追加／編集は**ダイアログ**（React Hook Form ＋ Zod）。カテゴリごとに項目定義。
- **公開タイミングはレコード単位で選択**（常時共有／死後開示）。
- 削除は `ConfirmDialog` で確認。楽観的更新で即時反映し、失敗時ロールバック。
- 並べ替えは `sort_order` を更新（MVP は任意）。

### カテゴリ別の項目（例）
| カテゴリ | 項目 |
|---|---|
| bank_account | 銀行名※必須 / 支店 / 種別 / 口座下 4 桁 / メモ |
| insurance | 保険会社※必須 / 種類 / 証券番号 / 連絡先 |
| property | 所在地※必須 / 種別 / 権利証の保管場所 |
| loan | 借入先※必須 / 種類 / 残高目安 / 連絡先 |
| account | サービス名※必須 / ID / 死後の希望（削除・残す・追悼） |
| subscription | サービス名※必須 / 料金 / 解約方法 |
| pet | 名前※必須 / 種類 / 動物病院 / 世話の方法 / 託したい人 |

### バリデーション（Zod）
- 必須項目：未入力なら「◯◯を入力してください」。
- 文字数：短文 100 字、メモ 1000 字程度。
- **口座番号は下 4 桁のみ**。フル桁・暗証番号・パスワード・マイナンバーの入力欄は**作らない**。
- 該当しそうな入力には注意文を表示（例「暗証番号は入力しないでください」）。

## 家族ロール時
- 追加・編集・削除ボタンを描画しない。カードは読み取り専用。
- `posthumous` の項目は解放前は API が返さないため、そもそも一覧に現れない。

# 3. 家族・共有管理 `/family`

## 目的
「常時共有」を成立させる。本サービスの価値が実際に届くかを決める画面。

## レイアウト
1. 見出しと説明：「ノートを共有する家族を招待します」
2. メンバー一覧：氏名／メール、ロール（本人・家族）、参加日、権限解除
3. 招待中の一覧：メール、有効期限、再送・取り消し
4. 「家族を招待」ボタン → ダイアログ（メール入力）
5. （v1）死後開示の発動導線 → `/family/disclosure`

## 仕様
- 招待：メール形式を検証。送信で `invitations` を作成し、招待メールを送る。
- 有効期限切れは「期限切れ」表示＋再送。
- 権限解除（`revoked`）は `ConfirmDialog` で確認。解除後は即座に閲覧不可。
- **owner は解除・降格できない**（UI から不可能にする）。
- 家族ロールでは、一覧は閲覧のみ。招待・解除は不可。
- 招待受諾フロー：`/invitations/[token]` → 未ログインならログイン／登録 → 受諾で `family_members` に追加 → `/dashboard`。
- 期限切れ・使用済みトークンは、その旨を表示（何のノートかは明かさない）。

## 監査
招待・受諾・権限解除は `audit_logs` に記録する。

# 4. LP `/`

## 目的
「終活＝重い」の心理的な敷居を下げ、**元気なうちに始める**気持ちを作る。SSG で SEO 対象。

## レイアウト（上から）
1. ヒーロー：ロゴ「ことづて」＋タグライン「いまを生きるための、終活ノート」＋`無料で始める`／`ログイン`
2. 課題提起：「もしもの時、家族はどこに何があるか分かりますか」
3. **価値の 3 点**：①家族と常時共有だから確実に届く ②項目に沿って迷わず書ける ③大切な人へ手紙を残せる
4. 使い方 3 ステップ：書く → 家族を招待する → いつでも見られる
5. 安心の説明：**暗証番号やパスワードは保存しない**（在りかだけを記録）
6. 注記：本サービスは遺言書ではなく、法的効力が必要な事項は正式な遺言書が必要
7. CTA ＋ フッター（プライバシーポリシー・利用規約・問い合わせ）

## 仕様
- SSG。`metadata`（title・description・OGP）を設定。構造化データを入れる。
- 死・不安を煽る表現は使わない。静かで前向きなトーン。
- ログイン済みでアクセスした場合は `/dashboard` への導線を出す。

# 5. ログイン `/login` ／ 新規登録 `/register`

## レイアウト
中央 1 カラムのカード。ロゴ、見出し、フォーム、相互リンク（未登録の方／既にアカウントをお持ちの方）。

## 仕様
- 登録項目：氏名、メール、パスワード（8 文字以上、確認用入力）。Zod で検証。
- ログイン項目：メール、パスワード、パスワードを忘れた方。
- **認証は Sanctum の SPA 認証**。ログイン前に CSRF クッキーを取得 → ログイン。**トークンをフロントで保持しない。**
- 失敗時は「メールアドレスまたはパスワードが正しくありません」（どちらが誤りか明かさない）。
- 送信中はボタンを無効化し二重送信を防ぐ。
- 成功後：元の URL があればそこへ、なければ `/dashboard`。招待経由なら受諾処理へ戻す。
- 登録直後に **`families` を 1 件自動作成**（本人＝owner）。

# 6. 招待の受諾 `/invitations/[token]`

## 目的
家族が最短で共有に参加できるようにする。**離脱を最小化する**のが最重要。

## 仕様
- トークン検証：有効／期限切れ／使用済み／不正 を判定。
- **有効な場合**：招待者の表示名と「◯◯さんからノートの共有に招待されています」を表示。
  - 未ログイン → ログイン／登録へ（**招待トークンを保持して戻す**）。
  - ログイン済み → `参加する` ボタン → `family_members` に追加 → `/dashboard`。
- **無効な場合**：期限切れ・使用済みはその旨のみ表示し、**何のノートか・誰の招待かは明かさない**。再送を依頼する案内を出す。
- 招待メールと異なるアカウントでログイン中の場合は注意を表示し、切り替えを促す。
- 受諾は `audit_logs` に記録。

# 7. 大切な人へ `/messages`

## 目的
事務情報とは切り離し、**言葉を残す場所**にする。

## レイアウト
説明文（1 行）＋手紙カードの一覧＋「＋ 手紙を書く」。空のときは `EmptyState`。

## 仕様
- 1 通＝宛先（例「妻へ」）＋本文。作成・編集・削除。
- **公開タイミングの既定は `posthumous`（死後開示）**。`TimingBadge` を表示し、切替可。
- 本文は複数行。自動保存（debounce 800ms）。文字数上限の目安を表示。
- 事務セクションと視覚的に差をつける（余白を広く、本文の行間を大きく）。
- 家族ロール：解放前は API が返さないため一覧に現れない。解放後は閲覧のみ。
- 削除は `ConfirmDialog`。

# 8. プレビュー／書き出し `/preview`

## 目的
ノート全体を通しで確認し、**紙で残す**手段を提供する。

## レイアウト
見出し（遺し文＝控え）、書き出しボタン（PDF／印刷）、全セクションを縦に整形表示。

## 仕様
- `always` と `posthumous` を通しで表示し、**死後開示の項目には鍵バッジ**を付ける（本人のみ全件）。
- 未記入項目は既定で非表示。「未記入も表示」トグルで切替。
- 印刷用スタイル（`@media print`）：ナビ・ボタンを隠し、ページ区切りをセクション単位に。
- PDF は印刷経由で可（MVP）。専用出力は v1（F-09）。
- 家族ロール：閲覧できる範囲のみ出力。
- 出力は `audit_logs` に記録。

# 9. 設定 `/settings`

## レイアウト（セクション区切り）
1. プロフィール：氏名、メール、パスワード変更
2. 公開タイミングの既定：新規項目を `always` / `posthumous` のどちらで作るか
3. **待機（撤回）期間**：3〜30 日のスライダー／数値入力。既定 7 日
4. 通知：見直しリマインド（年 1 回など）の有無
5. データ：全データのエクスポート
6. 危険な操作：退会

## 仕様
- 待機期間の説明を添える：「ご家族が死後開示を発動してから、実際に公開されるまでの猶予期間です。この間にご本人が取り消せます」。
- 各設定は個別保存（保存後にトースト）。
- 退会は `ConfirmDialog` ＋ パスワード再入力。**削除されるものを明示**し、家族にも見えなくなることを伝える。
- 家族ロール：自分のプロフィールと通知のみ。ノートの設定は表示しない。

# 10. 死後開示（v1）

## 発動 `/family/disclosure`（家族）

- 導線は `/family` 内に置き、**目立たせない**（誤操作防止）。
- 手順：説明を読む → `発動する` → **`ConfirmDialog`（重い確認文）** → **パスワード再入力（再認証）** → 発動。
- 確認文に明記：「ご本人に通知が届き、**{n} 日間**の猶予の後に公開されます。ご本人が取り消すこともできます」。
- 発動後は待機状態を表示（残り日数、取り消される可能性がある旨）。
- **既に `pending` がある場合は再発動できない**（二重発動防止）。

## 撤回 `/disclosure/[requestId]`（本人）

- 通知メールのリンクから直接到達。ログイン必須。
- 表示：誰がいつ発動したか、公開予定日時、`私は無事です（取り消す）` ボタン。
- 取り消すと `cancelled`。家族側にも結果を通知。
- 期限経過後は `released`。以後 `posthumous` の項目が家族に見えるようになる。
- 発動・撤回・解放はすべて `audit_logs` に記録。
